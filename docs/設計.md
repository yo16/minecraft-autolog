# minecraft-autolog 設計

2026-09-27 時点。技術調査([2026-09-26_技術調査.md](2026-09-26_技術調査.md))で実機確認した方式を前提に、実装に入れる粒度でまとめる。

## 1. 目的と範囲

### 1.1 目的

Minecraft(Java 版)をプレイしながら、**操作を止めず・フォーカスを奪わず・チャットも開かずに**、次を自動で記録する。

- 画面の様子(数秒おきの静止画)
- 話したコメント(音声 → 文字)
- ゲーム内の出来事(F2 スクショ、進捗、一時停止、ワールドの開始/終了)
- 一時停止を除いた実プレイ時間

そして、それらを [minecraft-log](https://github.com/yo16/minecraft-log) の `log.md`(日付見出し + 文章 + 画像の日記)に落とし込める形で出力する。autolog は minecraft-log の**入力を作るラッパー**であり、記事の文体や画像の扱いのルールは minecraft-log 側の `CLAUDE.md` に従う。

プレイ時間の大半は、黙って作業していて記事にならない時間である。したがって記録の大部分(5 秒おきの画像)は使われない前提で設計する。

- 記事に使った画像は minecraft-log にコピーされ、そちらが永続の置き場になる
- 使われなかった画像は autolog 側に**シーズン単位のアーカイブ**として残す。後から「あのときの様子」を見返せるが、リポジトリには入れない
- シーズン(ワールド開始〜エリトラ取得)が終わったら、そのシーズンのアーカイブを **1 コマンドでまとめて削除**できる。残す/消すの単位はシーズンで、ファイルを個別に選ばない

### 1.2 やらないこと(非目標)

- 動画の常時録画(必要になったら Xbox Game Bar の巻き戻し録画をホットキーで叩く程度に留める)
- Minecraft 側の改変(Mod・設定変更・F2 の自動送信)
- クラウドへの送信(音声・画像はすべてローカル)
- GUI(コンソール出力のみ。トレイ常駐などは将来)
- 記事の自動生成(下書きまで。文章に整えるのは minecraft-log 側の Claude との会話で行う)

### 1.3 前提

| 項目 | 値 |
|---|---|
| OS / Python | Windows 11 / Python 3.13(リポジトリの `.venv`) |
| Minecraft | Java 版 26.3 以降(SDL3 バックエンド)、バニラ、ウィンドウモード 854×480、`lang:ja_jp`、`pauseOnLostFocus:true` |
| マイク | あり(既定デバイス) |
| 文字起こし | faster-whisper `large-v3-turbo`(CPU、int8。HF キャッシュ取得済み) |
| 開発者 | 1 人。本人専用ツール |

## 2. 全体像

```
                 ┌──────────────────────────── Minecraft(前面のまま)───────────────────────────┐
                 │  画面(SDL3/OpenGL 窓)      logs/latest.log      saves/<w>/players/stats/<uuid>.json │
                 └──────┬────────────────────────┬───────────────────────────┬───────────────────┘
                        │ Windows Graphics Capture │ 0.5 秒ごとに差分読み     │ 更新監視
                        ▼                        ▼                           ▼
┌──────────────────────────────────────── autolog(常駐、1 プロセス)────────────────────────────────────┐
│  capture ─────┐   logwatch ─────┐   statwatch ─────┐   voice(recorder → transcriber) ─────┐            │
│  5 秒おきに   │   F2/チャット/  │   play_time      │   マイク常時 → 右 Ctrl で区切り      │            │
│  WebP 保存    │   進捗/一時停止 │   total_world_time│   → WAV → faster-whisper → 文        │            │
│               ▼                ▼                  ▼                                      ▼            │
│              ────────────────── events キュー ──────────────────────────────────────────────           │
│                                             │ writer(1 スレッド)                                       │
│                                             ▼                                                          │
│   seasons/<season>/sessions/<開始時刻>/ events.jsonl(追記のみ) + frames/*.webp + audio/*.wav + session.json│
└────────────────────────────────────────────────────────────────────────────────────────────────────────┘
                                              │ autolog export
                                              ▼
      seasons/<season>/export/<セッション>/ draft.md + images/(選んだ画像)  ──→  minecraft-log の log/seasonNN/ へ
                                                                              (Claude が CLAUDE.md の流儀で log.md に整形)
                                              │ シーズン終了後
                                              ▼
                              autolog purge <season>  → seasons/<season>/ の画像・音声をまとめて削除
```

設計の要点:

1. **記録はすべて時刻付きの追記(`events.jsonl`)**。モジュール同士は互いを知らず、キューに投げるだけ。1 つが死んでも他は動く
2. **画像とコメントの対応づけは記録時に行わない**。時刻だけ正確に残し、`export` 時に「この時刻の前後の画像」を選ぶ。選び方は後から変えられる
3. **音声は WAV で残す**。文字起こしの質は後からモデルや用語集を変えて上げられる
4. **文章に整えるのは minecraft-log 側**。autolog は事実(生の文字起こし・画像・時刻・出来事)だけを渡す
5. **記録はシーズン単位のフォルダに閉じ込める**。記事に使った画像は minecraft-log 側に写るので、シーズンが終わったら autolog 側のフォルダは丸ごと消せる

## 3. モジュール

### 3.1 window — Minecraft ウィンドウの検出

`poc/common.py` をそのまま昇格させる。

- `EnumWindows` で「タイトルが `^Minecraft\*?\s`、プロセスが `javaw.exe`/`java.exe`、クラス `SDL_app`」を探す。複数あれば面積最大
- 2 秒おきにポーリング。見つかったら **セッション開始**、10 秒以上見失ったら **セッション終了**。プロセスは終了せず次の起動を待つ(`--once` で終了)
- 提供する情報: hwnd、クライアント領域サイズ、前面かどうか、最小化かどうか

### 3.2 capture — 画面の定期保存

`poc/capture_loop.py` を昇格させる。

- `windows-capture` の `WindowsCapture(window_hwnd=…, cursor_capture=False, draw_border=False)`。フレームは画面が変化したときだけ届く
- `interval_s`(既定 5)ごとに 1 枚、クライアント領域に切り抜いて WebP(品質 80)で保存。ファイル名は F2 と同じ `YYYY-MM-DD_HH.MM.SS.webp`
- 各フレームで直前の保存画像との**差分**(縮小グレースケールの平均絶対差)を計算し、イベントに `diff` と `static`(差分がしきい値未満)を付ける。一時停止メニューや放置中の画像を export 時に避けるため。保存自体は間引かない(容量は約 50MB/時で問題ない)
- 前面かどうか(`foreground`)も付ける。別窓を見ている間はゲームが一時停止しているので、その画像は使いにくい
- 最小化中は撮れないので `warning` イベントを 1 回出し、戻ったら再開
- ウィンドウが閉じたら(`on_closed`)停止し、window モジュールのセッション終了に任せる

### 3.3 logwatch — latest.log の監視

`poc/tail_log.py` を昇格させる。

- **開きっぱなしにしない**。0.5 秒ごとに開いて前回位置から読み、閉じる(Minecraft は起動時に `latest.log` をリネームするため)。ファイルの identity(`st_ino`)やサイズ縮小で作り直しを検出し先頭から読み直す
- autolog 起動時に既存の `latest.log` を一度**全部読んで状態だけ復元**する(プレイヤー名・バージョン・ワールド名)。イベントとしては出さない。以後は末尾から追記分だけをイベント化
- 行には日付がないので、読み取った時刻の日付を付ける。行の時刻が現在時刻より 1 時間以上先なら前日とみなす(0 時またぎ対策)
- 抽出するイベント(日本語 UI と英語 UI の両方のパターンを持つ):

| kind | 元の行 | 備考 |
|---|---|---|
| `screenshot` | `[CHAT] スクリーンショットを<file>として保存しました` | イベント時刻はファイル名の時刻を優先(ログ行は約 1 秒遅れる) |
| `chat` | `[CHAT] <player> text` | 現状の設計では使わないが残す |
| `advancement` | `[CHAT] <player>が進捗[<name>]を達成しました` | |
| `death` | `[CHAT] <player>は…` で始まり進捗でないもの | 死亡メッセージの推定 |
| `pause` | `Saving and pausing game...` | Esc・フォーカス喪失 |
| `world_start` | `Starting integrated minecraft server version <v>` + `ServerLevel[<world>]` | ワールド名・バージョン |
| `world_stop` | `Stopping server` / `Stopping!` | |
| `login` | `Setting user: <player>` | |
| `system_chat` | 上記以外の `[CHAT]` | リスポーン地点設定など。記録はするが export では使わない |

### 3.4 statwatch — 実プレイ時間

- 対象: `saves/<world>/players/stats/<uuid>.json`。`<world>` は logwatch の `ServerLevel[...]` から(同名フォルダがなければ `saves/*/players/stats/*.json` の最新更新)。`<uuid>` はフォルダ内で最も新しいファイル
- 1 秒ごとに更新時刻を見て、変わっていたら読む。値は `minecraft:custom` の `minecraft:play_time`(**一時停止を除く**)と `minecraft:total_world_time`(含む)。tick 単位(1/20 秒)
- 更新のたびに `stats` イベント。Esc のたび・自動保存・終了時に書き直されるので、一時停止ごとの累積値が取れる
- **解除時刻の推定**: 直前に `pause`(時刻 T1、その時点の play_time P1)があり、次の `stats`(T2、P2)で P2 > P1 なら、解除 ≈ T2 − (P2 − P1)/20 秒。`resume_estimated` イベントとして出す(区間に停止が 1 回だけならほぼ正確)
- セッションの実プレイ時間 = セッション中の play_time の増分。ワールドを開いていた時間 = total_world_time の増分。`session.json` に書く

### 3.5 voice — 音声メモ

`poc/voice_note.py` を昇格させる。

- **recorder**: `sounddevice` でマイクを 16kHz モノラルで常時オープン。0.6 秒の先読みバッファを持ち、区切りの合図で録音区間を切り出す
- **区切りの合図**(`pynput` のグローバルフック。Minecraft のフォーカスは移らない):
  - `toggle`(既定): 右 Ctrl を押すと開始、もう一度で終了。ビープで状態を知らせる
  - `hold`: 押している間だけ(マウスのサイドボタン向き)
  - `vad`: 声の大きさで自動区切り(ハンズフリー。スピーカー環境では誤起動しうるので任意)
  - 90 秒を超えたら自動で区切る
- **transcriber**(別スレッド、直列処理): WAV 保存 → faster-whisper(`large-v3-turbo`、CPU int8、8 スレッド、ビーム幅 2、Silero VAD で無音除去)→ `note` イベント。実測で 7 秒の発話に 6〜8 秒
- **用語集** `glossary.txt`(リポジトリ直下、ユーザーが編集): 1 行 1 語を `initial_prompt` としてヒントに渡す(約 220 トークン ≒ 35〜40 語まで。上の行を優先し、起動時に採用数を表示)。`誤 => 正` の行は結果への置換ルール。置換前の文も `text_raw` として残す
- 無音の誤認識に多い定型句(「ご視聴ありがとうございました」など)が出たら `suspicious: true` を付ける
- マイクがない・フックが張れないときは voice だけを無効にして他は続行

### 3.6 writer — イベントの永続化

- 全モジュールは `queue.Queue` にイベント(dict)を入れるだけ。writer スレッドだけが `events.jsonl` に追記し、1 行ごとに flush する(途中でプロセスが落ちてもそこまでは残る)
- 同時にコンソールへ 1 行表示(時刻・種別・要約)。1 分ごとに状況(保存枚数・メモ数・実プレイ時間)を表示
- セッション開始/終了時に `session.json` を書く(終了時は集計を含めて上書き。5 分ごとにも中間保存)

### 3.7 export — minecraft-log への受け渡し

`autolog export <セッション> [--to <minecraft-log>/log/seasonNN]` で、1 セッションを minecraft-log が読める形にする。

1. **項目の抽出**: `note`(音声メモ)、`screenshot`(F2)、`advancement`、`death` を時刻順に並べる
2. **画像の選択**:
   - F2 の PNG は必ず含める(`.minecraft/screenshots` からコピー。今までの運用と同じ)
   - `note` には「話し始めの時刻以前で最も近い、`static` でなく `foreground` のフレーム」を 1 枚付ける(既定 `frames_per_note = 1`)。発話が 15 秒を超えるときは終わり際のフレームも 1 枚。同じフレームが複数の項目に選ばれたら 1 枚にまとめる
   - `advancement` / `death` は画像なし(直近の F2 やメモに寄せる)
3. **出力**: `export/<セッション>/` に
   - `images/` … 選んだ画像(F2 は PNG のまま、フレームは WebP のまま。名前は `YYYY-MM-DD_HH.MM.SS.拡張子`)
   - `draft.md` … 日付見出し(プレイ時間帯と**実プレイ時間**)、項目ごとに「時刻・生の文字起こし(`text_raw` があれば併記)・画像の相対参照」。出来事(進捗・死亡)は箇条書きで挟む
   - `entries.json` … 同じ内容の機械可読版(minecraft-log 側の Claude が読む)
4. `--to` を付けたら `images/` を指定フォルダの `images/` にコピーする。`log.md` の追記と `import_state.json` の更新は行わない(minecraft-log 側の流儀に任せる)
5. 選んだ画像の一覧を `entries.json` の `images` に、コピー先を `copied_to` に記録する。これが「記事に使った(候補になった)画像」の台帳になり、`status` / `purge` が参照する

`draft.md` の例:

```markdown
## 2026-09-27(21:03頃〜23:10、実プレイ約1時間40分。ワールドを開いていた時間は約2時間05分)

- 21:05:12 🎙 「ピリジャーがウロウロしているので、ちょっと隠れてます」
  ![](images/2026-09-27_21.05.10.webp)
- 21:12:40 📷 F2
  ![](images/2026-09-27_21.12.40.png)
- 21:20:03 🏆 進捗「石器時代」
- 21:31:55 🎙 「これから木を伐りますが、本当はオークではなくトウヒがほしい」(置換前: 「…気を罰りますが…」)
  ![](images/2026-09-27_21.31.50.webp)
```

### 3.8 archive / purge — 使わなかった記録の後始末

- **セッションは必ずシーズンのフォルダの下に作る**(§4.1)。シーズン名は次の順で決める
  1. `config.toml` の `season`(明示)
  2. minecraft-log の `log/import_state.json` の `current_season`(`minecraft_log_dir` が設定されていれば読む)
  3. どちらもなければワールド名(`world-20260920`)
- `python -m autolog status`: シーズンごとに、セッション数・フレーム枚数・音声本数・容量、export 済みか、記事に使った画像数を表示する。「消してよいか」を判断するための一覧
- `python -m autolog purge <season>`: そのシーズンの **`frames/` と `export/*/images/` を削除**する(容量の大半)。`events.jsonl` `session.json` `entries.json` `draft.md` と `audio/` は残す(小さく、何をしたかの履歴として価値がある)。`--audio` で音声も、`--all` でフォルダごと削除。実行前に対象と容量を表示して確認を求める(`--yes` で省略)
- export で選ばれた画像は minecraft-log にコピー済みなので、purge で消えても記事は壊れない。念のため purge は「そのシーズンに export されていないセッションがある」場合に警告する
- 任意: `capture.keep = "near_events"` にすると、セッション終了時に「メモ・F2・進捗のどれからも `near_events_window_s`(既定 120 秒)以上離れたフレーム」を削除する。黙って作業している時間の画像をそもそも残さない設定。既定は `"all"`(アーカイブとして残す)

## 4. データ形式

### 4.1 保存場所

```
<data_dir>/                          既定 %LOCALAPPDATA%\minecraft-autolog(config.toml で変更可)
  seasons/
    season02/                        シーズン終了後は purge の対象。--all ならこのフォルダごと消える
      sessions/
        2026-09-27_21.03.14/         セッション開始時刻
          session.json
          events.jsonl
          frames/2026-09-27_21.03.19.webp …     ← purge で消える
          audio/2026-09-27_21.05.12.wav …       ← purge --audio で消える
      export/
        2026-09-27_21.03.14/
          draft.md
          entries.json               選んだ画像とコピー先の台帳
          images/                    ← purge で消える(minecraft-log にコピー済み)
    season03/
  autolog.log                        プロセス自身のログ(警告・例外)
```

リポジトリには入れない(サイズが大きく、個人データ)。`.gitignore` に `sessions/` `export/` `seasons/` を入れておく。

シーズンをまたいで見返したいものは、記事(minecraft-log)にあるものだけ、という割り切り。「記事にしなかったが残したい」画像が出てきたら、その場で minecraft-log の `images/` に手でコピーするか、`draft.md` に追記して export し直す。

### 4.2 events.jsonl

1 行 1 イベント。共通フィールドは `time`(ローカル時刻、ISO 8601、ミリ秒)と `kind`。パスはセッションフォルダからの相対。

```jsonc

{"time":"2026-09-27T21:03:14.105","kind":"minecraft_state","player":"greenbanana17","version":"26.3","world":"20260920","world_open":true}
{"time":"2026-09-27T21:03:19.004","kind":"frame","file":"frames/2026-09-27_21.03.19.webp","bytes":61234,"diff":0.182,"static":false,"foreground":true}
{"time":"2026-09-27T21:03:20.500","kind":"world_start","version":"26.3","world":"20260920","player":"greenbanana17"}
{"time":"2026-09-27T21:03:21.000","kind":"stats","saved_at":"2026-09-27T21:03:20.880","world":"20260920","play_time":225311,"total_world_time":499804}
```

`resume_estimated` は算出できた時点で書くので、行の並びは `time` 順にならないことがある。読む側は `time` でソートする。

補足(M1 の実装で決めたこと):

- `minecraft_state`: セッション開始時点で latest.log から分かっている状態。autolog を Minecraft より後に起動したときに、`world_start` がなくてもワールド名・プレイヤー名が分かるようにする
- `stats` の `time` は読み取った時刻、`saved_at` は統計ファイルの更新時刻(Minecraft が保存した時刻)。解除時刻の推定には `saved_at` を使う。基準値はワールド開始時とセッション開始時に、更新がなくても 1 回出す
- `advancement` の `frame` は `task`(進捗)/ `goal`(目標)/ `challenge`(挑戦)
- `info`: 最小化から戻って撮影を再開した、などのお知らせ
- 窓が出る前(最大 120 秒)のイベント(ログイン行など)は溜めておき、セッション開始時にそのセッションへ書く
- コンソールには `frame` を 1 枚ずつは出さず、1 分ごとの状況表示にまとめる

## 6. 動作の流れ

### 6.1 通常のセッション

1. ターミナルで `python -m autolog start` を起動(Minecraft の前後どちらでもよい)。モデル読み込み(約 4 秒)とマイクの準備をして待機
2. Minecraft を起動しワールドに入る → window が窓を検出 → `session_start`。capture が撮り始め、logwatch が `world_start` を、statwatch が最初の `stats` を出す
3. プレイ中: 5 秒おきに `frame`。F2 を押せば `screenshot`。右 Ctrl → 話す → 右 Ctrl で `note`(数秒後に文が表示される)。Esc で `pause` と `stats`
4. ワールドを出る/Minecraft を閉じる → `world_stop` → 窓が消えて 10 秒で `session_end`、`session.json` を確定
5. 好きなタイミングで `python -m autolog export latest --to D:\Public\github\yo16\minecraft-log\log\season02` → `draft.md` と `images/` ができ、画像が minecraft-log にコピーされる
6. minecraft-log のチャットで「autolog の export を取り込んで」と頼む → Claude が `entries.json`/`draft.md` と画像を読み、`CLAUDE.md` の流儀で `log.md` に追記する。ボツにした画像は minecraft-log 側で削除する(autolog 側のアーカイブには残る)

### 6.2 シーズンの終わり

1. エリトラを取得し、minecraft-log でシーズンの記録を締める
2. `python -m autolog status` で、そのシーズンの全セッションが export 済みであることと容量を確認する
3. `python -m autolog purge season02` で画像を削除する(履歴と音声は残る)。ディスクが気になれば `--all`
4. 次のワールドを始めると、minecraft-log の `current_season` に従って `seasons/season03/` に記録が始まる

### 6.3 minecraft-log 側に必要な変更(別リポジトリ、提案)

`CLAUDE.md` の運用フローに「autolog からの取り込み」を追加する。

1. 指定された `export/<セッション>/entries.json` を読む
2. `images/` の画像はすでにコピー済みなので、内容を確認しながら各項目の生の文字起こしを日記調の文章に整える(事実の追加はしない。`text_raw` との差は聞き間違いの修正なので `text` を採用)
3. 日付見出しの時間帯・所要時間は `session.json` の実プレイ時間を使う(従来の「最初のスクショ〜最後のスクショ」より正確)
4. シーズン README の累計プレイ時間も実プレイ時間で更新する
5. 画像は WebP を許容する(GitHub の Markdown で表示できる。従来の「PNG のまま」は F2 分にだけ適用)

## 7. 非機能要件

| 項目 | 方針 |
|---|---|
| ゲームへの影響 | capture は変化時のみ・5 秒に 1 回のエンコード(数十 ms)。文字起こしは発話ごとに数秒の CPU バースト(8 スレッド)。カクつくなら `threads` を 4 に |
| メモリ | モデル約 1GB + フレームは即保存で保持しない。合計 2GB 未満を目安 |
| ディスク | フレーム約 50MB/時、音声約 2MB/分(話した時間のみ)。1 シーズン(20 時間)で 1〜2GB |
| 耐障害性 | モジュールごとに独立したスレッドと例外処理。1 つが死んでも `warning` を出して他は継続。`events.jsonl` は 1 行ごとに flush |
| 時刻 | すべて PC のローカル時刻。Minecraft のログも同じ時計なので突き合わせに補正は不要 |
| プライバシー | すべてローカル。マイクは区切りの間だけ保存(`vad` モードは常時解析するが保存は発話区間のみ)。データはリポジトリ外 |
| 依存 | `pywin32` `windows-capture`(numpy, opencv) `sounddevice` `pynput` `faster-whisper`。すべて pip |

## 8. 実装の順序

| 段階 | 内容 | 完了条件 |
|---|---|---|
| M1 | `autolog start`: window + capture + logwatch + statwatch + writer。voice なし | 1 セッション通して `events.jsonl` と `session.json` ができ、実プレイ時間が統計と一致する |
| M2 | voice の統合、`devices` / `transcribe` コマンド、用語集の移動 | プレイ中に右 Ctrl で `note` が入り、`export` なしでも `events.jsonl` から追える |
| M3 | `export`、`status`、`purge` と minecraft-log の `CLAUDE.md` 更新 | export → minecraft-log で 1 日分の `log.md` を作れる。手作業のスクショ報告より楽になっている。`purge` で 1 シーズン分を安全に消せる |
| M4 | 仕上げ | `vad` の実地調整、Minecraft 起動と同時に立ち上げるショートカット、トレイ常駐、必要なら Game Bar 連携の短い動画 |

各段階の終わりに `tests/` の純粋関数テストを通し、main にコミットして push する。
